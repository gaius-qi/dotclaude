# Go comments

Reference codebase: [dragonflyoss/dragonfly](https://github.com/dragonflyoss/dragonfly). Language guides where they don't contradict: [Go Doc Comments](https://go.dev/doc/comment), [Google Go Style: Commentary](https://google.github.io/styleguide/go/decisions#commentary). When they disagree, dragonfly wins. Test code carries no comments: `testing.md`.

```go
// HostManager is the interface used for host manager.
type HostManager interface {
	// Load returns host for a key.
	Load(string) (*Host, bool)

	// IsBlobURL reports whether the url is an OCI blob URL.
	IsBlobURL(string) bool
}

// hostManager contains content for host manager.
type hostManager struct {
	// AdvertiseIP is advertise ip.
	AdvertiseIP net.IP

	// Server port.
	Port int
}

// Load returns host for a key.
func (h *hostManager) Load(key string) (*Host, bool) {
	// Look up the host in the local map first.
	if host, ok := h.Map.Load(key); ok {
		return host.(*Host), true
	}

	// Fall back to the persistent store, refer to https://github.com/dragonflyoss/dragonfly/pull/652.
	return h.loadPersistent(key)
}
```

## Doc comments

- Every top-level declaration, interface method and struct field gets a `//` doc comment directly above it, no blank line. Unexported declarations too, so a rename-to-export needs no edit.
- Full sentence, starts with the identifier, third-person present, ends with a period: `// Len returns the length of host map.` Boolean funcs use `reports whether`, never "or not".
- Constructors keep dragonfly's noun form: `// New host manager interface.` above `newHostManager`. Match the file.
- Interface methods are documented once; the implementation repeats the comment verbatim.
- Struct fields: sentence `// AdvertiseIP is advertise ip.` or phrase `// Server port.`, matching the struct you edit. `manager/models/*.go` packs fields without blank lines; keep that there.
- Grouped `const (` / `var (`: one doc comment per entry, blank line between entries. Not the go.dev end-of-line style.
- No `// Package x ...` in `scheduler/`, `manager/`, `internal/`, `cmd/`. A reusable `pkg/` library may carry one in its primary file (`pkg/oci/reference.go`), never a `doc.go`.
- gin handlers in `manager/handlers/*.go` carry swagger annotations (`// @Summary`, `// @Router`) instead of a doc comment. Copy the sibling handler's block.
- Deprecation is its own paragraph after the doc: blank `//`, then `// Deprecated: use AnnouncePeer instead.`
- Generated files start with `// Code generated by MockGen. DO NOT EDIT.` and are never hand-edited.

## Body comments

- One step comment per logical block: capitalized imperative sentence, trailing period, blank line before it. `// Initialize cache.`, `// Marshal scopes of client.` Label the step, not the syntax; never one per line.
- Longer notes wrap onto following `//` lines.
- No trailing same-line comments except a lint pragma naming the linter: `ctx.Error(err) // nolint: errcheck`.
- Cite sources with a bare URL at the end of the sentence: `// refer to https://...` No markdown links, angle brackets or issue numbers.
- Only `TODO`, in go.dev form: `// TODO(fu220): Implement the following methods.` No `FIXME`, `NOTE`, `XXX`, `HACK`.
- `/* */` only for the license header. No commented-out code.
- Directives: `//go:generate` between the license and `package`; `//go:build` on line 1 above the license.
- Nothing enforces this beyond `misspell`; `.golangci.yml` excludes the `comments` preset. Review is the gate.
